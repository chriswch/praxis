# Tech-talk slides

For sharing-session and conference slides. Slides are a visual aid for speech, not a document — the cardinal error is making them a teleprompter, so the audience reads instead of listening.

- **Assertion-Evidence (Michael Alley)** — the single most valuable swap for technical talks. The headline is a full-sentence *claim*; beneath it sits one piece of *visual evidence* — not bulleted text. ("Caching cut P95 latency 40×" + one line chart, not "Performance" + five bullets.) Better understood, better remembered, delivered with more confidence.
- **Presentation Zen (Garr Reynolds)** — simplicity, whitespace, one idea per slide. Fuller slides transfer less; cognitive load is finite.
- **Storytelling with Data (Knaflic)** — strip chart clutter (gridlines, extra labels, 3D); use pre-attentive attributes (color, weight) to steer the eye to the one number that matters. A chart points to a conclusion; it isn't decoration.
- **Nancy Duarte (Resonate / slide:ology)** — whole-talk story arc: oscillate between "what is" and "what could be," build tension, end on a call to action. For sessions meant to persuade or inspire, not merely report.
- **Big-text schools** — Takahashi / Lessig (huge words, very short lines); Kawasaki 10/20/30 (10 slides, 20 minutes, ≥30pt type).
- **Slides ≠ docs** — push detail to a written follow-up or repo; on stage, use a live demo and few slides. The audience should leave with "why it matters" and "where to go deeper," not a transcribed spec.
- **Producing the file** — this covers slide *content and structure*; to generate the actual .pptx, compose with the `pptx` skill.
